# 虚拟手柄 · VirtualGamepad

一个跑在 Android 上的虚拟手柄。

在屏幕上叠一层可自定义的虚拟按键，把点按转换成标准 Linux 输入事件
（经由 `/dev/uinput`），让系统像对待真实手柄一样处理。

## 运行条件

- Android 8.0（API 26）及以上
- 平时不需要联网（仅点「检查更新」时联网一次）

需要以下**任一**授权：

- **Shizuku**（通过 root 或无线调试激活）
- **ADB**：无线调试 / 电脑 adb / Termux / LADB
- **root**

守护进程以 `uid 2000`（adb shell）或 `uid 0`（root）运行，
两者都行 —— Shizuku 不是唯一途径。

## 功能

**布局**
- 多布局系统：默认手柄、默认键盘、自定义布局
- 每个布局独立保存，带创建时间
- 布局可导出 / 导入 / 分享

**编辑**
- 拖动改位置，带吸附对齐
- 大小、透明度、字体大小可调
- 背景颜色自定义：预设色板 / 网页取色 / 手动输入 `#AARRGGBB`
- 透明度支持百分比与十进制两种单位，可点击切换

**穿透**
- 触摸穿透开关，开 / 关两套独立配色
- 采用 `touchableRegion` 区域方案

**其他**
- 收起成悬浮小球，再展开
- 组合键：动作序列、方向、触发方式、摇杆模式、延迟
- 主界面 UI 元素可隐藏
- 内置更新日志，升级后只提示新增部分

## 技术说明

**输入注入**：经 `/dev/uinput` 写入标准 Linux 输入事件，
与真实外设走同一条链路，不走无障碍服务。

**targetSdk 为什么固定 28**：
升到 30+ 会触发包可见性限制、后台启动前台服务受限等问题，
而本工程依赖的正是前台服务 + 悬浮窗，故刻意保持 28。

**触摸穿透**：
采用 `WindowManager.LayoutParams.touchableRegion` 区域方案，
而非某些方案中"压低窗口 alpha"的做法，
因此不受 Android 12+ / 16 上 alpha 限制策略变化的影响。

**检查更新**：
依次尝试 GitHub Releases API → jsDelivr 镜像 → raw。
Release 说明里写一行 `versionCode: 385080` 用于比对；
另写 `网盘: <地址>` 可指定网盘入口。

## 隐私

本产品的网络行为仅限两项：

1. **本机回环**（127.0.0.1）Socket 通信 —— 守护进程与 UI 之间的通道
2. **检查更新** —— 用户主动点击时，向本仓库发起一次 HTTPS GET

除上述两项外，不连接任何其他服务器，不上传任何数据，
不含任何第三方统计 / 广告 SDK。

不点击「检查更新」则全程不会产生任何对外网络请求。

# 虚拟手柄 · 一页速查卡

基线：2026-09-19 最终版，**`PROTOCOL_VERSION = 5`**。细节查《虚拟手柄_结构化手册.md》。

> ⚠️ v4 → v5：键盘换 NKRO bitmap，无 6 键上限。**必须 pkill → 重装 → 重跑启动命令**，否则第 7 个键照样丢。

---

## 每次改完 HID 相关代码，三步走（漏一步就白改）

```bash
pkill -f [G]padDaemon          # 方括号不能省，见下方「两个新坑」
ps -A | grep -i [g]pad         # 必须确认无残留
# AIDE 重装 APK → 回 app 点「复制命令」→ 重跑
```

HID 描述符是守护进程创建 `/dev/uhid` 那一刻注册给内核的，**重装 app 不会碰它**。

## 启动命令

```
CLASSPATH=/data/app/com.example.vgamepad-xxx/base.apk \
app_process / com.example.vgamepad.GpadDaemon
```

路径不确定就 `pm path com.example.vgamepad`。
**挂起不返回 = 正常**（读 stdin 保活）。后台跑：
```bash
nohup CLASSPATH=... app_process / com.example.vgamepad.GpadDaemon > /sdcard/vg.log 2>&1 &
```

正常输出顺序：
```
Virtual Gamepad ready on 127.0.0.1:19820
kernel opened device: true
listening on 127.0.0.1:19820
alive 5s, clients=0, cmds=0 (waiting)     ← 持续出现才算活着
client connected (#1)                     ← app 启动手柄后
```

## 浮层状态灯

| 灯 | 怎么办 |
|---|---|
| 🟢 已连接 v5，已发送 N | 正常。N 涨但游戏没动 = 游戏没识别；N 不涨 = 触摸没进来 |
| 🟠 连上的是旧进程 | 没杀干净 → pkill 后重跑 |
| 🟠 不认识版本查询 | **多半不是版本旧**，见下方 |
| 🟠 守护进程比本 app 新 | app 旧了 → 重装 app，别 pkill |
| 🔴 守护进程未连接 | 进程没起来 / 缺 INTERNET 权限 |

## 两个新坑（本版新增）

**① `pkill -f GpadDaemon` 会自杀**
执行它的 shell 命令行里本身含 "GpadDaemon"，`pkill -f` 匹配完整命令行，把自己也杀了 → 后面的 `ps` 没跑完 → 表现为"守护进程还在"。

```bash
pkill -f [G]padDaemon
ps -A | grep -i [g]pad
kill -9 <pid>      # 兜底
```

**②「不认识版本查询」真因是守护进程被一个连接卡死**
`serve()` 阻塞在本线程 → `accept()` 执行不到 → 第二个连接待在 backlog 没人接。而 TCP 握手由内核完成，app `connect()` 成功、看着"连上了"，但 `?` 永远等不到回答，2.5 秒超时后取 -1。
修法：每客户端独立线程 + 握手重试一次（300ms）+ 解析放宽（`VGPAD 4` / `VGPAD4` 都认）。

## 决策表

| daemon | app | 结论 |
|---|---|---|
| 无输出，执行完即退出 | 红 | 进程被回收，查心跳 |
| EADDRINUSE | 红 | 旧进程占位 + app 侧问题（多半缺 INTERNET 权限） |
| EADDRINUSE | 绿 | 正常，旧进程在服务 |
| listening + alive | 红 | app 侧：权限 / APK 未重装 |
| listening + alive | 绿，cmds 不涨 | 链路通，游戏没识别 |
| listening + alive | 绿，cmds 增长 | 完全正常 |

## 触摸穿透（本版核心机制）

- **区域方案**，不是 alpha 方案：反射设 `TOUCHABLE_INSETS_REGION`，区域外**窗口压根不存在**
- alpha 可保持 1.0，不受 Android 12「alpha ≤ 0.8 才能穿透」限制，整手柄只需 1 个窗口
- 替代「每键一个窗口」——键盘 80+ 键会被系统批量回收导致崩溃
- 反射失败自动回退多窗口；主界面「当前穿透模式」显示实际生效模式
- 失效时的退路：主界面勾「强制多窗口模式」
- **别删 region 提交的两处重试**（commit ×3 @60ms、settle ×5 @80ms），删了会抖动

---

## 三个「别动」

1. **targetSdk 保持 28**（30+ 包可见性、31+ 禁后台起前台服务、34+ 强制服务类型）
2. **不要加 `<queries>`**（老 aapt 不认识 → 资源编译失败 → 只有新 id 报 Unknown member）
3. **不要 `waitFor()`** 守护进程；stdout/stderr 两个流都要抽

## 编辑模式易踩

- **加元素后检查所有命中判定的区间循环起止点**（画得出点不到的经典成因）
- **判断身份用 padType / proto**，不按下标（副本槽位的 L2 下标不是 9）
- 覆盖顺序：「固定显示」里**强制显示必须排在隐藏之前**，否则永远出不来
- 界面按钮（编/收/布/透）**不给删**——删了「编」就再也进不了编辑模式
- **`sliderValue()` 里摇杆设置必须排在 `isMulti()` 之前**，否则多选+摇杆设置读到的是"大小"
- **`clearSelection()` 必须同时退子模式**（`mShapeMode` / `mStickCfg`），否则读 `widthMul[-1]` 崩溃

## 多选（本版重构）

一个状态管三件事，不用再记三套开关：

```
常用工具 -> 多选… -> 勾几个 -> 确定
拖其中一个             -> 整批跟着走（原「关联挪动」）
滑条（大小/透明/字体） -> 作用于整批（原「多选调节」）
更多选项 -> 外观 -> 形状 -> 整批刷圆形/四边形（原「多选形状」）
```

- 原「关联挪动」改名「多选…」；「键盘按键…/手柄按键…」合并为「按键创建…」
- 按在**已选中**的按钮上不会取消多选（以前一按就清空，批量拖动没法用）
- 选中不存盘：切布局 / 重置 / 退出编辑都清空
- 多选时不给「摇杆设置」

## 组合键（本版最大新功能）

按一下发一段小宏，手柄键 / 键盘键 / 摇杆 / 十字键 / 扳机可混放，中间能插延迟。说明文档里**没写**。

```
按键创建… → 组合键 → 先选「按钮 / 十字架」→ 摆位置
选中 → 更多选项 → 编辑组合键 → ＋ 添加按键
```

动作类型 11 种：
```
1  手柄键按下     （扳机时 tag = 力度 0–100）
2  键盘键按下     3  延迟(ms)
4  全松（老数据） 5  结束手柄键   6  结束键盘键
7  摇杆推方向     8  十字键拨方向
9  摇杆回中       10 十字键回中   11 摇杆自定义坐标
```
延迟档位：30 50 80 100 150 200 300 500 800 1000 1500 2000
方向号 0–7：上 右上 右 右下 下 左下 左 左上（斜向已归一化 ±0.7071）

> 摇杆 / 十字键不能存成类型 1——以前会误发 `BTN_START`。执行端现在对类型 1 遇到 `I_LS`/`I_RS`/`I_DPAD` 直接跳过。

**十字架**：一个按钮四条独立序列（上下左右），按落点决定跑哪条；斜角默认开（左上 = 左+上）。不自动改名。

**播放语义**：按下启动序列，**跑完再统一松开**。
- 点一下就松手 → 序列照跑，播完自动松开
- 一直按着 → 播完保持按住，松手才松开
- 只松开"已经发出去"的；末尾留 60ms 让最后一帧能采样到
- 无延迟的序列不加收尾，保持"按住"手感

> 以前"松手即中断"：延迟后面的键永远不触发，等于延迟功能整个失效。

## 横竖屏同步

布局列表每行的「同步」按钮（内置布局不给）。三步：选方向 → 勾按钮 → 勾属性。

- 属性：大小 / 透明 / 字体 / 其他信息（形状、隐藏、摇杆固定与范围、宽高倍率）
- **位置默认不复制**（比例不同会跑出屏幕），但目标方向压根没这个按钮时沿用源位置当落点，免得飞到 (0,0)
- **身份字段强制复制**（`pt`/`k`/`bl`/`cn`/`ca`），否则目标槽位还是空的，看着像"同步了没过来"

## 按键外观（「外观」永远排更多选项第 1 位）

子列表四项：**形状 / 改名 / 改背景颜色 / 按键名**

**改背景颜色**：12 档固定色 + 两种自定义（都跳 app 界面，会先确认）
- **网页调色盘** — `assets/color_picker.html` 走 WebView 的 `<input type="color">`
- **手输 `#RRGGBB`** — 认 `#RRGGBB` / `RRGGBB` / `#RGB` / `#AARRGGBB`

> Android 没有公开的取色 Intent，但 WebView 实现了 HTML color input → 弹出原生面板。
> 初值走 URL 参数 `?c=RRGGBB&n=3`，不会"先闪白再变当前色"。
> **初值不能一律给白**：界面按钮底色是专用画笔写死的（编/布=紫、收=红、透=绿/红），要用 `defaultColorOf(i)`。

**穿透按钮有两支颜色**：取色前先挑"开 / 关"（`mColorPassState` 1 / 2）。

**布局调节**（多选时）：大小滑条切成**整体缩放倍率**（0.35–1.60），按钮连间距一起朝**中心按钮**聚。中心只在已勾选的那批里挑。

## 悬浮球 G（本版新生）

独立槽位 `I_FLOAT = 198`（`N = 199`）+ 独立内置布局「悬浮窗」`LAYOUT_FLOAT = 31`，专门调 G 的样式。

> 以前 G 复用「收」：一点全部重置就被打回「收」，用户改的蓝底白字全没了；且两者共用 scale/颜色/名字，改一个另一个跟着变。
> `LAYOUT_FLOAT` 取 31 而不是 2：2 已被老用户的第一个布局占用，挪 `LAYOUT_USER_START` 会让存档串味。
> G 的位置恒等于「收」。

## 空白按钮

按键创建 → 空白。**只占位置、不画名字、按下去什么都不发**。能拖 / 调大小透明度形状 / 隐藏 / 删除。上限 16（槽位 166–181）。

## 摇杆（固定 / 浮动）

| 属性 | 默认 |
|---|---|
| `stickFixed` | true（固定） |
| `stickRange` | 1.5（范围 0.5–3.0） |

「更多选项 → 摇杆设置」只有摇杆有。关掉固定后，按在 `半径 × stickRange` 圈内 → 摇杆瞬移到手指位置。固定开着时范围滑条不给拖。
`hitFloatStick()` 必须存在——否则预览圈画得老大、实际只有摇杆本身按得动（圈是骗人的）。
